1. What ISODocks does

ISODocks turns Revit piping into isometric documentation, by two routes. You can use either, or both.

RouteWhat you getWhat you need
3D ISO Isometric views generated inside Revit and placed on sheets. Revit only.
PCF export A PCF file that AutoCAD Plant 3D turns into a fabrication isometric, with bill of materials, weld list and cut list. Revit, plus an AutoCAD entitlement.

The second route does not reproduce ISOGEN — it feeds it. ISOGEN has handled isometric layout, dimensioning and spooling for decades; ISODocks builds the file it expects from your Revit model.

2. Requirements

  • Revit 2024, 2025, 2026 or 2027.
  • An Autodesk account, signed in to Revit.
  • An internet connection at start-up, at least once every 14 days.
  • For PCF export only: AutoCAD with the Plant 3D toolset. Anyone with an AutoCAD entitlement has it (One AutoCAD, 2019 and later). A standalone Revit subscription does not include it.

4. Settings

Open Settings before anything else. Settings are stored per project, inside the Revit file, so they travel with it.

SettingNotes
Driver parameterThe parameter whose value identifies each pipeline. Elements sharing a value form one line. Required.
Auto-tag new elementsA value written into the driver parameter as you draw, so you do not have to tag by hand. OFF disables it. See section 6.
View templateApplied to the generated 3D isometric views.
Title blockUsed when placing those views on sheets.
Sheet fit marginHow much of the title block a view fills, between 0.50 and 0.95.
Pipe hanger familyWhich family your hangers use. See section 5 — without this, hangers are treated as ordinary fittings.
SKEY parameterThe family type parameter holding the symbol code. Usually ISO_SKEY. Optional.
End type parameterThe family type parameter holding the joint code. Usually ISO_ENDTYPE. Optional.
Plant 3D projectBrowse to the project's Project.xml. ISODocks reads that project's symbol map so it can offer and check valid codes. Only needed for PCF export.
PCF output folderWhere the files are written. Leave blank to use the Plant 3D project folder. If neither is set, ISODocks uses the model's folder, then your Desktop. The export report says which it used.

Preparing the view template

Two entries in the template's include list decide whether ISODocks can do its job. Everything else in the template is yours to set as you like.

Template entrySettingWhy
V/G Overrides Filters Unchecked ISODocks applies its own filters to each generated view. When the template includes filters, the template wins and the tool cannot set them.
View Scale Your choice Checked: every drawing comes out at the same scale, so they compare directly, but a long line may not fit its title block. Unchecked: ISODocks scales each view to fill the sheet, so everything fits at whatever scale it needs.

5. Tagging your pipelines

ISODocks groups elements into pipelines by the value of the driver parameter. Give every pipe, fitting and accessory on a line the same value; give a different line a different value. That value becomes the line's name on the drawing and the name of its PCF file.

Hangers

Revit has no element type for a pipe hanger, so ISODocks cannot find them on its own. A hanger is recognised only when all of the following are true:

  • it is modelled as a pipe fitting;
  • it has connectors and cuts the pipe — the pipe runs into it from both sides;
  • its family is named in Settings under Pipe hanger family.

Once declared, hangers are handled correctly on both routes: the isometric passes through them so a hangered pipe still reads as one continuous run, and the PCF export writes them as supports. A hanger family that is not declared is treated as an ordinary fitting, which puts a joint in the drawing where there is none.

Hangers need no driver parameter value of their own.

Branch connections — no spuds

Where a smaller line branches off a larger one, the larger pipe must be split at the branch so the branch fitting sits between two pipes.

Spud connections are not supported — that is, a fitting set onto a pipe that runs through in one piece. Revit allows it and it looks right in 3D, but ISODocks cannot express it: the branch is written as a separate run and Plant 3D draws it on its own sheet, reporting a disconnect.

If a branch appears on a drawing of its own, check whether the header it comes off is one continuous pipe. Split it at the branch point and export again.

A tee, or any fitting placed so the pipe is divided at it, needs nothing special — this applies only to fittings set onto an undivided pipe.

Connectivity check

The Generate window has a Check connectivity button. It walks each line and reports three things:

FindingMeaning
IslandAn element carrying the line's value but not connected to the rest of it. Always an error — usually a mis-tagged fitting or a broken connection.
Split groupTwo separate networks sharing one value. An error, and the dangerous one: it produces a drawing showing two unrelated runs, and it looks plausible.
Open endA connector leading nowhere. Usually correct; listed for you to check, not flagged as a problem.

Findings are selected in the model so you can see them straight away. Worth running on a model you have not generated or exported before.

6. Tagging as you draw

Setting the driver parameter on every element by hand is the slowest part of preparing a model. Auto-tag does it as you work.

In Settings, next to the driver parameter, choose or type a value. From then on, every pipe, fitting and accessory you place is given that value. Set it back to OFF when you are done.

Three rules govern it, and they follow from one principle: ISODocks never overwrites a value that already exists.

SituationWhat happens
You place something into an existing line It inherits that line's value, not the one in the field. A valve cut into PL5 becomes PL5 even if the field says PL2.
You place something in open space It takes the value from the field. If you later connect it to a different line, the original value stays — correct it by hand.
You place something that joins two lines It takes the value from the field, and ISODocks warns you so you can check.
You copy or paste tagged elements Their values are kept. Set auto-tag to OFF before pasting elements that already carry line values you want to preserve — pasted elements without a value would otherwise be given the current one.

Auto-tag is stored with the project, so it is remembered between sessions. It is worth switching it off when you finish a run of drawing.

7. 3D isometrics

Generate ISO lists every pipeline it found, with the number of elements in each. Tick as many as you like and generate them in one pass — there is no need to work line by line. Select all and Clear handle the whole list.

Each row has a magnifier button that selects and zooms to that line in the model, so you can confirm you are about to generate the right thing.

Include directly-connected mechanical equipment pulls in tanks, pumps and similar that a line runs into, so the drawing shows what it connects to. Leave it off for a drawing of the pipework alone.

Regenerate works the same way but lists only the lines that already have views, and rebuilds them after the model has changed.

Tags annotates the generated views, and Place on Sheets lays them out using the title block and fit margin from Settings.

This route needs nothing beyond Revit, and is the right choice if you have no Plant 3D entitlement.

8. PCF export

Export runs in three steps.

  1. Choose the lines. The same picker as Generate, with the same magnifier buttons and the same mechanical-equipment option.
  2. Fill the title block values. See section 11. These are remembered, so on later exports this step is a confirmation.
  3. Export. One PCF file per line, named after the line.

Then in Plant 3D, open your project and run PCF to Iso from the Isos tab. The drawings appear in the project's isometric output folder.

PCF is self-contained: it carries the geometry, sizes, symbol codes and joint types, so Plant 3D does not need a matching specification or catalogue to render it.

The export report lists, per line, what was found and any warnings. Read the warnings — they name the family and the code involved.

9. Preparing your families

ISODocks works out most of what it needs from Revit itself. What it cannot know is which symbol to draw and which joint to show, because Revit has no equivalent of either. Two codes supply them.

CodeMeaningExamples
ISO_SKEYWhich symbol the isometric draws for this component.ELBW elbow · TEBW tee · VBFL ball valve · VYFL butterfly valve
ISO_ENDTYPEWhich joint symbol appears where this component meets the pipe.PPL fusion weld (PE, PP) · BW butt weld · FL flanged · P press fitting · SC threaded · C soldered · GL glued

Add both as shared parameters, of type Text, bound to Pipe Fittings and Pipe Accessories as type parameters. Type, not instance: the symbol and joint are properties of the family type, so setting them once covers every placement.

A library that carries these two parameters needs no further configuration. ISODocks reads them and exports correctly with an empty mapping file.

Where a family does not carry them, ISODocks falls back — first to the project's mapping file, then to a sensible default derived from the Revit part type. It warns rather than guessing when nothing fits.

10. The mapping window

The mapping window lists every fitting and accessory family type in your model and shows where each one's codes come from.

SourceMeaning
familyFrom the family's own parameter. Locked here — change it in the family.
fileFrom this project's mapping file.
defaultDerived from the Revit part type. Nothing to do unless it is wrong.
MISSINGNo code from any source. Only accessories reach this state, because Revit gives them no part type.

Use the search box and the part type filter to narrow the list, select several rows and apply a code to all of them at once, or tick Needs a SKEY only to see just the gaps.

If you have set a Plant 3D project folder, the dropdowns offer only codes that project can actually draw, and the Problem column tells you straight away if a code will not resolve.

Where your settings are kept

ISODocks writes two small text files beside your model: one holding the symbol and joint codes from this window, and one holding the title block values you enter when exporting. Both are named after the model.

On a workshared project they sit beside the central model, so your whole team shares them. Where the model has no writable folder of its own — a cloud-hosted project, for example — they are kept in your own Windows user profile folder instead, and ISODocks tells you so when it saves. In that case they are not shared with your team, and each person builds up their own.

Both files are written by ISODocks and should not be edited by hand. A new project starts from the codes built up in previous projects; after that the two are independent, so editing one project never changes another.

11. Setting up Plant 3D

Most PCF problems are Plant 3D configuration rather than anything in the file. Five settings catch people out, and every one of them is invisible until the output looks wrong.

  1. Use a metric project for metric models. The unit system is fixed when the project is created and cannot be changed afterwards. An imperial project rejects a metric PCF outright — nothing renders and no reason is given.
  2. Turn dimensioning on. It is off in the default iso style.
  3. The weld list only appears in the Final style, not in Check. A missing weld list is usually the style, not the file.
  4. Overflow drawings look empty when the material lists do not spill onto them. That is expected.
  5. Where a drawing splits is a style setting, not something the file controls.

If a symbol is missing from a drawing, Plant 3D substitutes a placeholder and still reports the run as successful — the detail is in its log, not in the summary. Open the log file from the Isometric Creation Results window; it names the code it could not find. ISODocks warns about these before you export, provided you have set the Plant 3D project folder in Settings.

12. Title block values

Exporting asks for the values that fill your iso title block — medium, pipe class, project name, and whatever else your style defines. The form is built from the style's own configuration, so it matches whichever title block you render with.

Values are remembered for next time and apply to every line in one export; if lines need different values, export those lines separately.

Each PCF file is named after its line, and ISODocks also writes the line name into whichever attribute your style maps to LineNumber — which is why that row does not appear on the form. Whether it then reaches the sheet depends on your title block having a matching attribute definition. If the line name does not appear where you expect it, or turns up in the wrong box, that is the style configuration rather than the export: check that IsoConfig.xml and the title block in the .dwt still agree.

13. Troubleshooting

SituationWhat to check
Nothing is found to exportThe driver parameter in Settings, and that your elements carry a value in it.
One drawing shows two unrelated runsA split group — two networks share one driver value. The connectivity check finds these.
A component draws as a placeholder boxIts symbol code is not one the iso style can draw. Open Mapping and look at the Problem column.
Joints look wrong for plastic pipeThe end type. Fusion-welded PE and PP need PPL, not BW.
No weld list on the drawingThe iso style. Use Final, not Check.
The file will not render at allUnit system: a metric file needs a metric project.
Your teammate has different mappingsOn a cloud-hosted model the mapping cannot sit beside the central file and is kept per user. The save message tells you when this happens.
A branch appears on its own drawingA spud connection — the pipe it branches from is not split at the branch point. See section 5.
Plant 3D reports a disconnectUsually a spud connection, or a genuine gap in the model. Run Check connectivity first.
Filters are not applied to the viewsThe view template includes V/G Overrides Filters. See section 4.
The drawing does not fit its title blockThe view template fixes the scale. Exclude View Scale from the template to let each view fill its sheet.
Output looks unchanged after a fixRe-run PCF to Iso and reopen the drawing. A stale drawing on screen is the most common false alarm.

14. License verification

At start-up ISODocks checks with the Autodesk App Store that your account is licensed. It sends your Autodesk user identifier and the app identifier, and nothing else — no model data, no file names, no usage information. The result is cached so the add-in keeps working offline. If verification has not succeeded for 14 days, you will be asked to reconnect.

About / Privacy stays available even if verification fails, so you can always read the disclosure and reach us. Full detail is in the privacy policy.
